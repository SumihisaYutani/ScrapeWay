## 1. 概要

ScrapeWay は、Web 上の小説を **投稿・公開されたときの形式のまま** 手元に保存し、オフラインで読むための Windows デスクトップアプリである。

### 1.1 対応サイト

| サイト | 取り込み単位 | 原本として保存するもの |
|---|---|---|
| pixiv 小説 | ユーザーの全小説 / シリーズ / 1話 | 本文（pixiv 記法のまま）と API の作品情報 |
| Wayback Machine (web.archive.org) | 開いたページと、そこからのリンク先・同じフォルダ内の保存ページ | 当時の HTML・画像などのバイト列そのまま |

ノクターンノベルズなど他サイトへの対応は今後の課題（[9章](#9-今後の課題)）。

### 1.2 基本方針

1. **原本を改変しない。** 取得したデータは原本として別ファイルに保存し、閲覧用ファイルは原本からいつでも作り直せるようにする。
2. **サイトに負荷をかけない。** 取得は1件ずつ順番に行い、件数ごとに待ち時間を入れる（既定 3 秒）。
3. **単体で動く。** Python などのランタイムは不要。Qt の DLL と一緒にフォルダごと配布する。

## 3. 全体構成

### 3.1 モジュール

```
ScrapeWay.exe ─┬─ mainwindow   画面（取り込み・ライブラリ・メニュー）
               ├─ jobs         保存ジョブを1本のスレッドで順に処理
               ├─ chromelogin  pixiv ログイン（Chrome/Edge を起動して Cookie を取得）
               │    └─ cdpsocket  DevTools 接続用の最小 WebSocket クライアント
               └─ scrapeway_core（静的ライブラリ。画面に依存しない）
                    ├─ pixiv      pixiv の一覧取得・保存・閲覧用 HTML 生成
                    ├─ wayback    Wayback の一覧取得・保存・リンク張り替え
                    ├─ net        同期 HTTP クライアント（再試行・中止つき）
                    ├─ textcodec  日本語の文字コード判定と変換
                    ├─ util       ファイル入出力・正規表現置換・HTML→平文
                    ├─ paths      設定ファイルと保存場所
                    └─ model      取り込み一覧の共通データ型
```

| ファイル | 役割 |
|---|---|
| `src/main.cpp` | 起動。引数に URL があればすぐ読み込む |
| `src/mainwindow.*` | メインウィンドウ |
| `src/jobs.*` | `Job`（保存作業1件）と `JobWorker`（処理スレッド） |
| `src/chromelogin.*` | ログイン処理 |
| `src/cdpsocket.*` | RFC 6455 の必要部分だけを実装した ws:// クライアント |
| `src/pixiv.*` | pixiv 対応 |
| `src/wayback.*` | Wayback Machine 対応 |
| `src/net.*` | HTTP |
| `src/textcodec.*` | 文字コード |
| `src/util.*` | 共通処理 |
| `src/paths.*` | 設定と保存場所 |
| `src/model.h` | `Item` / `ResolveResult` / `LogFn` |
| `resources/reader.html` | pixiv 閲覧用 HTML のテンプレート（Qt リソースに埋め込み） |
| `tests/cli.cpp` | 開発用 CLI（配布しない） |
| `tests/cdptest.cpp` | DevTools 接続の確認用（配布しない） |

### 3.2 スレッド

| スレッド | 担当 |
|---|---|
| GUI スレッド | 画面、ログイン処理（非同期 I/O） |
| `QtConcurrent` のスレッドプール | 一覧の取得（resolve）、ライブラリの読み込み、起動時の閲覧用 HTML 再生成 |
| `JobWorker`（1本） | 保存。同時に複数のジョブを走らせず、キューに入れた順に処理する |

`net::Http` は作ったスレッド内でだけ使う（内部の `QNetworkAccessManager` がスレッドに属するため）。

### 3.3 処理の流れ

```
URL 入力 ──▶ resolve（スレッドプール）──▶ 一覧表示・選択 ──▶ Job 作成
                                                          │
                     JobWorker: 1件ずつ保存 ◀───────────────┘
                       │  ├─ 件と件の間に待ち時間
                       │  └─ 進捗・ログをシグナルで画面へ
                       ▼
                 （Wayback のみ）サイトの閲覧用ページをまとめて生成
                       ▼
                 ライブラリを再読み込み
```

## 4. 機能仕様

### 4.1 URL の判定

入力が `pixiv.net` のホストなら pixiv、それ以外はすべて Wayback として扱う。

| 種類 | 受け付ける形 |
|---|---|
| pixiv ユーザー | `https://www.pixiv.net/users/<ID>`（`/novels` などが続いてもよい） |
| pixiv シリーズ | `https://www.pixiv.net/novel/series/<ID>` |
| pixiv 1話 | `https://www.pixiv.net/novel/show.php?id=<ID>`、`https://www.pixiv.net/n/<ID>` |
| Wayback | `https://web.archive.org/web/<時刻>[フラグ]/<元のURL>`。時刻は 1〜14 桁、フラグ（`id_` など）は無視 |
| 元の URL のみ | `http://example.com/…`。現在時刻に一番近い保存を使う |

元の URL は比較用に正規化する（フラグメント除去、ホストを小文字に、既定ポート `:80` / `:443` を省く、空のパスは `/`）。`http:/x` のように斜線が1本のものは補う。

### 4.2 pixiv

#### 一覧の取得（resolve）

| 入力 | 使う API（`https://www.pixiv.net/ajax/` 以下） |
|---|---|
| ユーザー | `user/<id>` → `user/<id>/profile/all` → `user/<id>/profile/novels?ids[]=…`（50件ずつ） |
| シリーズ | `novel/series/<id>` → `novel/series/<id>/content_titles`（`available` のものだけ）→ `profile/novels` |
| 1話 | `novel/<id>` |

- 並び順：シリーズの話はシリーズ ID・話数の順、その後に単発作品を投稿日の新しい順。
- 状態：保存済みの `meta.json` が無ければ「未保存」。あれば、一覧の `updateDate` が保存時の `uploadDate` より新しいとき「更新あり」、それ以外は「保存済み」。
- ログインしていない状態でユーザーの小説が 0 件のときは、「R-18 作品の場合はログインが必要です」と警告する。

#### 保存

1. `novel/<id>` を取得し、`content` を取り出して `content.txt` に書く。
2. 表紙（`coverUrl`）を `cover.<拡張子>` に保存する。古い `cover.*` は消す。
3. 挿絵を `images/` に保存する。
   - `[uploadedimage:ID]`：`textEmbeddedImages` の `urls.original`
   - `[pixivimage:作品ID]` / `[pixivimage:作品ID-ページ]`：`illust/<作品ID>/pages` の該当ページの `urls.original`
4. 作品情報（本文以外）に `_savedAt`（保存日時）と `_textCount`（`characterCount`、無ければ空白を除いた文字数）を足して `meta.json` に書く。**`meta.json` があることを「保存が完了した」印とするので、最後に書く。**
5. `novel.html` を生成する。

すでに保存済みの話は、同じフォルダに上書きする（題名が変わってもフォルダ名は変えない）。

#### 閲覧用 HTML（`novel.html`）

`resources/reader.html` に値を差し込んで作る。pixiv 記法の変換は次のとおり。

| 記法 | 変換後 |
|---|---|
| `[newpage]` | ページ区切り（`<section class="page" id="pN">`） |
| `[chapter:題]` | `<h2>` |
| `[[rb:親文字 > ルビ]]` | `<ruby>` |
| `[[jumpuri:表示 > URL]]` | 外部リンク（`http` で始まるものだけ） |
| `[jump:N]` | 同じ作品の N ページ目へのリンク |
| `[uploadedimage:…]` / `[pixivimage:…]` | 保存した画像。無ければ記法のまま |

キャプションは平文に直して表示する（`<br>` は改行、タグは除く）。シリーズ作品には前後の話へのリンクを付ける（同じシリーズフォルダ内の相対パス）。

読書画面の機能：縦書き／横書きの切り替え、文字サイズ（12〜32px）、配色（白・セピア・黒）。設定はブラウザの localStorage に保存する（失敗しても表示は崩れない）。縦書きのときは、マウスホイールで左右に送る。

### 4.3 Wayback Machine

#### 一覧の取得（resolve）

1. 開いたページを `https://web.archive.org/web/<時刻>id_/<URL>` で取得する。`id_` を付けると、Wayback のツールバーやリンク書き換えが入らない当時の原本が返る。取得するのは「消えていない最新の版」と「入力した日時に一番近い版」の2つで、両方のリンクを合わせる（版によってリンクが減っていても、各話を拾えるようにするため）。
2. 文字コードを判定してページの題名とリンクを取り出す。対象は次のとおり。
   - `<a href>`（リンク文字。無ければ画像の `alt`、それも無ければ `</a>` の直後の文字を最大 60 字）
   - `<frame src>` / `<iframe src>` / `<area href>`
   - 同じサイト（`www.` の有無は区別しない）で、画像・CSS などではないもの
3. 同じフォルダ以下の保存ページを CDX API で調べる。

   ```
   https://web.archive.org/cdx/search/cdx?url=<ホスト(www.なし)><フォルダ>
     &matchType=prefix&output=json&fl=original,timestamp,mimetype,length
     &filter=statuscode:200&collapse=urlkey&limit=10000
   ```

   MIME タイプに `html` を含むもの、または `text/plain` のものを対象にする。

4. 次の3グループにまとめる。

| グループ | 内容 | 最初のチェック |
|---|---|---|
| 開いたページ | 入力した URL | 未保存なら入れる |
| このページからのリンク | 2. のリンク先（出てきた順に #1, #2 …） | 未保存なら入れる |
| 同じフォルダ内のその他の保存ページ | 3. のうちリンクされていないもの（パス順） | 入れない |

- 状態：`site.json` に記録があれば「保存済み」。同じフォルダ内のリンク先なのに CDX の結果に無いものは「Wayback になし」として、チェックを外す（CDX の結果が上限の 10,000 件に達したときは判定しない）。
- サイズは CDX の `length`（圧縮後の大きさなので目安）。日付は **最初に記録された日時**（`collapse=urlkey` は一番古い記録を返すため）で、実際に保存される版の日付ではない。保存した版の日付はログとライブラリに出る。
- 状態は保存したかどうかだけで判定する。保存済みのページを保存し直すと、その時点で消えていない最新の版に更新される。
- フォルダが `/` でなければ、一つ上のフォルダで一覧を取り直すための URL（`parentUrl`）を返す。

#### 保存する版の選び方（消えていない最新の版）

各ページについて、**消えていない最新の版だけ** を保存する。過去の版は残さない。

1. CDX API でそのページの記録を一覧にする（`url=<URL>&output=json&fl=timestamp,digest&filter=statuscode:200`）。404・410・転送（3xx）・サーバーエラーの記録はここで除かれる。内容（`digest`）が同じ記録は一番新しい1つにまとめ、新しい順に並べる。
2. 新しい版から順に、`web/<撮影時刻>id_/<URL>` で取得して確かめる（最大 6 版）。次のものは使わず、1つ前の版に進む。
   - 取得できない（HTTP 200 以外）
   - 別のページへ転送される（Wayback の URL に含まれる元の URL が、求めたページと違う）
   - 「消えたページ」と判断される（下記）
3. 使える版が1つも無ければ「消えていない版が見つかりませんでした」として失敗にする。
4. 保存済みの版の撮影時刻が、選ばれる版と同じなら取得し直さない。違えば原本を上書きする。
5. 最新の記録を使わなかったときは、ログに理由と、実際に保存した版の日付を出す。

**消えたページの判定**（正常（200）として記録されているが、中身がお知らせになっているもの）

- 題名に次のいずれかを含む：`404`、`Not Found`、`Forbidden`、`error`、`エラー`、`見つかりません`、`存在しません`、`削除されました`、`閉鎖`、`移転しました`、`サービス…終了`、`ジオシティーズ`
- または、本文（script と style を除いた文字）が 1,500 字未満で、次のいずれかを含む：`Not Found`、`ページが（は）見つかりません`、`お探しのページ`、`ファイルが見つかりません`、`存在しません`、`削除されました`、`閉鎖しました`、`閉鎖いたしました`、`移転しました`、`サービスを終了`、`公開を終了`

長い本文の中に出てくる言葉では判定しない（小説の文章を誤ってお知らせと判断しないため）。消えたページと判断した内容の `digest` は `site.json` の `goneDigests` に記録し、同じサイトの他のページでは取得せずに飛ばす（サイト共通の閉鎖のお知らせなど）。

#### 一時停止への対応

Internet Archive は混雑すると「Temporarily Offline」のお知らせページを返すことがある。Wayback への通信はすべて共通の関数を通し、次のように扱う。

- お知らせページを受け取ったら 60 秒待ってやり直す（最大 3 回）。それでも止まっていれば保存ジョブを打ち切る（保存済みの分は残る）。
- CDX の結果が JSON の配列でなければ、「記録なし」とは扱わずエラーにする。

#### 保存

1. 上の方法で選んだ版を取得し、撮影時刻と `digest` を記録する。
2. 原本を `original/<パス>` にそのまま書く。
3. HTML なら、同じサイトの付属ファイルも原本として保存する。間隔は 0.5 秒、やり直しは 1 回（10 秒待ち）まで。取れなかったものは、理由（404、Wayback 側の壊れた記録による 502 など）にかかわらず `missing` として記録し、次のページからは取り直さない。
   - `<img src>`、`<input src>`、`<embed src>`、`<bgsound src>`、`<script src>`
   - `body` / `table` / `td` / `th` の `background`
   - `<link href>` のうち `.css` `.ico` `.png` `.gif` `.jpg` `.jpeg`
4. `site.json` にページの情報を書く。
5. ジョブの最後に、関係したサイトの閲覧用ページ（`view/`）と `index.html` をまとめて作り直す。

#### 保存先のパス

| 元の URL | 保存先（サイトフォルダからの相対パス） |
|---|---|
| `/novel/` | `novel/index.html` |
| `/novel/ch1.htm` | `novel/ch1.htm` |
| `/novel/ch1`（HTML） | `novel/ch1.html` |
| `/bbs.cgi?no=3`（HTML） | `bbs.cgi@no=3.html` |

各パス要素の `\ / : * ? " < > | # %` と改行・タブは `_` に置き換え、末尾の空白とピリオドを除く。80 字を超える場合は、先頭 71 字に `~` と元の名前の SHA-1 の先頭 8 桁を付ける（切り詰めた結果、別のページと同じ名前になるのを防ぐため）。`dir/` と `dir/index.html` は同じファイルになる（同じページを指すため）。Windows の予約名（`con`、`nul` など）には先頭に `_` を付ける。

#### 閲覧用ページ（`view/`）

- 原本を判定した文字コードで読み、UTF-8 で書き出す。
- `href` / `src` / `background` / `action` を次のように張り替える。
  1. 保存済みのページ → `view/` 内の相対パス
  2. 保存済みの付属ファイル → `original/` 内の相対パス
  3. それ以外 → `https://web.archive.org/web/<撮影時刻>/<URL>`（Wayback 上のページ）

  ページ内リンク（`#…`）、`javascript:`、`mailto:` は変えない。
- 文字コード指定の `<meta>` を除いて、`<meta charset="utf-8">` を入れる。
- `<body>` の直後に、撮影日・保存ページ一覧へのリンク・Wayback で開くリンクを載せた帯を入れる（フレーム分割のページには入れない）。
- HTML でないテキスト（`text/plain`）は、BOM 付き UTF-8 に変換する。それ以外はそのまま複写する。

### 4.4 文字コードの判定（textcodec）

判定は次の順で行う。

1. 先頭 8KB の `<meta … charset=…>`。ただし「UTF-8 と書いてあるが UTF-8 として不正」なら使わない。
2. HTTP の `Content-Type` の `charset`。`ISO-8859-1` / `US-ASCII`（サーバーの既定値として付いていることが多い）と、不正な UTF-8 は使わない。
3. 中身から推測する。
   - BOM → UTF-8
   - エスケープ列（`ESC $ B` など）→ ISO-2022-JP
   - ASCII のみ、または UTF-8 として正しい → UTF-8
   - それ以外は Shift_JIS と EUC-JP の不正バイト数を比べて、少ないほうにする。同数なら Shift_JIS。

変換には Windows の `MultiByteToWideChar` を使う。

| 文字コード | コードページ |
|---|---|
| Shift_JIS（CP932） | 932 |
| EUC-JP | 20932 |
| ISO-2022-JP | 50220 |
| windows-1252 | 1252 |
| EUC-KR | 51949 |
| Big5 | 950 |
| GBK | 936 |

UTF-8 / UTF-16 は Qt で変換する。名前の揺れ（`x-sjis`、`windows-31j`、`x-euc-jp` など）は正規化する。

### 4.5 pixiv ログイン（chromelogin）

外部のアプリが普段の Chrome から Cookie を読むことはできない。Chrome 136 以降は既定のプロファイルへのデバッグ接続が禁止されており、Cookie もアプリ固有の暗号化で守られているためである。そこで、専用プロファイルを使って2段階で行う。

1. **対話段階**：Chrome（無ければ Edge）を、`--user-data-dir=<専用プロファイル>` を付けて **デバッグ接続なしで** pixiv のログインページで開く。デバッグ接続を付けると、Google ログインが「安全でないブラウザ」として拒否されるためである。利用者はログインしてからブラウザを閉じる。
   - 起動から 3 秒以内にプロセスが終わったときは、既に開いている同じプロファイルのブラウザに引き渡されたとみなし、エラーにする。
2. **読み取り段階**：同じプロファイルを `--headless=new --remote-debugging-port=0` で起動する。
   1. プロファイル内の `DevToolsActivePort` からポートとパスを読む。
   2. `/json/version` から WebSocket の URL と User-Agent を得る（`HeadlessChrome` は `Chrome` に置き換える）。
   3. `Storage.getCookies` を最大 3 回まで呼ぶ（1 秒おき）。
   4. ドメインが `pixiv.net` で終わる Cookie のうち、`PHPSESSID` が `<数字>_…` の形ならログイン済みとみなし、その数字をユーザー ID とする。
   5. `Browser.close` で終了させる。全体で 30 秒を超えたら失敗。3 秒後にまだ残っていれば強制終了する。
3. Cookie 文字列・ユーザー ID・User-Agent・ユーザー名（`ajax/user/<id>`）を `pixiv_session.json` に保存する。

### 4.6 通信（net::Http）

| 項目 | 内容 |
|---|---|
| User-Agent | ログイン時に取得した値。無ければ Chrome 相当の固定値 |
| Referer | pixiv / pximg のホストに対してだけ `https://www.pixiv.net/` を付ける（画像サーバーが要求するため） |
| Cookie | pixiv の API を呼ぶときだけ付ける。Qt の自動 Cookie 処理は使わない |
| タイムアウト | 1 回の転送が 60 秒止まったら打ち切る |
| 再試行 | HTTP 429 / 5xx は 10・40・90 秒待って最大 3 回。通信エラーは 5・10・15 秒待って最大 3 回。回数は呼び出しごとに指定できる（Wayback の付属ファイルは 1 回）。待つときはログに理由と秒数を出す |
| 中止 | 待ち時間中も 0.1 秒ごとに中止フラグを確認し、立っていれば `"中止しました"` の例外を投げる |

### 4.7 保存ジョブ

| 項目 | 内容 |
|---|---|
| 単位 | 「選択した N 件を保存」1回につき1ジョブ |
| 状態 | 待機中 → 保存中 → 完了 / 中止 |
| 間隔 | 件と件の間に、画面で指定した秒数（1〜60、既定 3）待つ |
| 失敗 | 1件の失敗はログに残して次へ進む（失敗数を表示） |
| 中止 | 待機中なら即座に中止。保存中なら、今の通信または待ち時間が終わった時点で止まる。保存済みの分は残る |
| 終了時 | 保存中に閉じようとすると確認する。閉じるときは全ジョブを中止して最大 10 秒待つ |

### 4.8 ライブラリ

- 起動時とジョブ終了時に、保存フォルダを読み直す。
- 起動時に、すべての閲覧用ファイル（pixiv の `novel.html`、Wayback の `view/` と `index.html`）を原本から作り直す。これにより、テンプレートを変えたときや、ジョブの途中でアプリを閉じたときも整合が取れる。
- 表示は次のとおり。
  - pixiv：作者 → シリーズ（または単発作品）→ 話。更新の新しい順。表紙を小さく表示する。
  - Wayback：サイト（ホスト）→ 最初のフォルダ（複数あるときだけ）→ ページ。
- 検索：題名・作者・シリーズ名・タグ（Wayback は題名・URL・ホスト）の部分一致。大文字と小文字は区別しない。

## 6. データ仕様

### 6.1 保存場所

| 種類 | 通常 | ポータブル版（exe と同じ場所に `portable.txt` がある） |
|---|---|---|
| 設定 | `%APPDATA%\ScrapeWay\settings.ini` | `<exe>\data\settings.ini` |
| ログイン情報 | `%APPDATA%\ScrapeWay\pixiv_session.json` | `<exe>\data\pixiv_session.json` |
| ログイン用プロファイル | `%APPDATA%\ScrapeWay\profiles\pixiv\` | `<exe>\data\profiles\pixiv\` |
| 作品（既定） | `ドキュメント\ScrapeWay\` | 同左（設定で変更可） |

`settings.ini` のキー：

| キー | 内容 | 既定値 |
|---|---|---|
| `libraryDir` | 作品の保存先 | `ドキュメント\ScrapeWay` |
| `wait` | 取得間隔（秒） | 3 |

> `pixiv_session.json` とログイン用プロファイルには、pixiv のログイン状態が入っている。他人に渡さないこと。

### 6.2 pixiv の保存形式

```
<保存先>\pixiv\<ユーザーID>_<名前(30字)>\
    series_<シリーズID>_<シリーズ名(40字)>\
        001_<話ID>_<題名(40字)>\
            content.txt     本文（UTF-8、pixiv 記法のまま）
            meta.json       作品情報（API の body から content を除いたもの + _savedAt, _textCount）
            novel.html      閲覧用（自動生成）
            cover.jpg       表紙
            images\uploaded_<ID>.<拡張子>
            images\pixiv_<作品ID>[-<ページ>].<拡張子>
    <話ID>_<題名>\          単発作品
```

名前に使えない文字（`\ / : * ? " < > |` と改行・タブ）は `_` に置き換え、前後の空白とピリオドを除く。

### 6.3 Wayback の保存形式

```
<保存先>\wayback\<ホスト名>\
    original\<パス>     原本（受け取ったバイト列そのまま）
    view\<パス>         閲覧用（自動生成）
    site.json           保存の記録
    index.html          保存したページの目次（自動生成）
```

`site.json` の形：

```json
{
  "host": "www.example.jp",
  "pages": {
    "<キー>": {
      "url": "http://www.example.jp/novel/ch1.htm",
      "file": "novel/ch1.htm",
      "ts": "20050101123456",
      "digest": "AOTEQJPFP5…",
      "contentType": "text/html",
      "charset": "Shift_JIS",
      "html": true,
      "title": "第一話",
      "size": 12345,
      "savedAt": "2026-10-25T12:00:00"
    }
  },
  "goneDigests": ["Q27FN323RY…"],
  "assets": {
    "<キー>": { "url": "…", "file": "img/bg.gif", "ts": "…", "contentType": "image/gif" },
    "<キー>": { "url": "…", "missing": true, "status": 502 }
  }
}
```

キーは `www.` を除いたホスト + パス（+ `?クエリ`）。http と https は区別しない。

### 6.4 pixiv_session.json

```json
{ "user_id": "123", "user_name": "…", "cookie": "PHPSESSID=…; …", "user_agent": "Mozilla/5.0 …", "saved_at": "…" }
```

## 7. ビルドと配布

### 7.1 配布物の作成

`build.bat` を実行する。

1. Visual Studio 2022 の環境を読み込み、Qt 6.10.3 MSVC2022 で Release ビルドする。
2. `dist\ScrapeWay\` に exe を置き、`windeployqt` で Qt の DLL を集める。翻訳ファイル・D3D/DXC コンパイラ・ソフトウェア OpenGL は除く。
3. VC++ ランタイムの DLL を同梱し、`docs\manual.html` を複写する。
4. `dist\ScrapeWay.zip` を作る（約 14MB。展開後は約 33MB）。

### 7.2 Qt Creator

`CMakeLists.txt` をそのまま開く。キットは「Desktop Qt 6.10.3 MinGW 64-bit」または「MSVC2022 64bit」。

### 7.3 CMake のターゲット

| ターゲット | 内容 | 配布 |
|---|---|---|
| `scrapeway_core` | 取得・保存の本体（静的ライブラリ） | ― |
| `ScrapeWay` | アプリ本体 | する |

## 10. 注意事項

- 保存した作品の著作権は作者にある。保存は私的な利用の範囲にとどめる。
- 取得間隔を極端に短くしない。pixiv も Wayback Machine も、短時間の大量アクセスは制限や利用停止の対象になる。
